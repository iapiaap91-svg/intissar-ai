# Intissar AI

تطبيق Flutter لتسجيل الصوت وتحويله إلى نص محلياً بالكامل (بدون إنترنت)، بدعم متعدد اللغات (عربية / فرنسية / إنجليزية / دارجة)، مع فصل متحدثين، تصحيح لغوي، أرشيف مشفَّر قابل للبحث، استيراد مستندات، تحليل صور، أسئلة وأجوبة، اختبارات تفاعلية، وتصدير — **على أندرويد وiOS وWindows وLinux**.

## حالة المشروع (تقييم واقعي، وليس تسويقياً)

| المرحلة | المحتوى | الحالة الفعلية |
|---|---|---|
| Phase 1 | تسجيل صوت محلي + Whisper (عبر `whisper_ggml_plus`) | ✅ تعمل فعلياً — تدعم أندرويد/iOS/Windows/Linux/macOS |
| Phase 2 | فصل متحدثين (تقريب بالطاقة الصوتية) + تصحيح لغوي + تداخل لغوي | ✅ تعمل، دقة الفصل بين المتحدثين محدودة (راجع الملاحظات) |
| Phase 3 | استخراج PDF/Word/PowerPoint حقيقي + OCR عربي/فرنسي حقيقي (Tesseract) | ✅ تعمل للنص المطبوع، ضعيفة على الخط اليدوي |
| Phase 4 | إجابة أسئلة + توليد اختبارات من المحتوى الفعلي | ✅ تعمل، لكنها **استخراجية** وليست توليدية (راجع الملاحظات) |
| Phase 5 | تصدير PDF بعربية مُشكَّلة بصرياً بشكل صحيح + تصدير الصوت الأصلي | ✅ تعمل، تتطلب وضع خط عربي (راجع الخطوات) |
| Phase 6 | أرشيف محلي مشفَّر (SQLCipher/AES-256) للتسجيلات مع بحث وفلترة | ✅ تعمل — حفظ آلي بعد كل تسجيل، مفتاح التشفير في خزنة النظام الآمنة |
| Phase 7 | دعم سطح المكتب (Windows/Linux): تحديث تلقائي (Inno Setup / AppImage) | ✅ مبني، ينتظر أول بناء واختبار فعلي عبر CI |
| Phase 8 | CI/CD كامل: بناء APK/exe/AppImage تلقائياً + فحص أمني (CodeQL/Semgrep) | ✅ مبني عبر GitHub Actions، ينتظر أول تشغيل فعلي |

**لا يوجد "مكتمل 100%" بمعنى منتج نهائي جاهز للنشر** — كل مرحلة نسخة أولى تعمل فعلياً (وليست محاكاة)، لكنها تحتاج اختباراً ميدانياً حقيقياً على أجهزة وتسجيلات فعلية قبل أي استخدام إنتاجي. راجع `PROJECT_STATE.md` للتفاصيل الكاملة والنقاط غير المؤكدة تقنياً (لم يُصرَّف الكود بعد فعلياً في أي بيئة محلية).

## خطوات التشغيل والإعداد اليدوي (إلزامية قبل أول تشغيل محلي)

1. تثبيت Flutter SDK 3.x فأعلى: https://docs.flutter.dev/get-started/install
2. `flutter pub get`
3. توليد مجلدات المنصات (مرة واحدة فقط، محلياً أو تُولَّد تلقائياً داخل CI):
   `flutter create --platforms=android,windows,linux .`
4. إضافة أذونات أندرويد (ميكروفون، تخزين، خدمة أمامية) إلى
   `android/app/src/main/AndroidManifest.xml` — القائمة الكاملة في `PROJECT_STATE.md`.
5. **نموذج Whisper**: لا يُضمَّن يدوياً في `assets/` — التطبيق يحمّله عند الطلب من داخل شاشة "إعدادات النموذج" (⚙️ في الشريط العلوي)، مع شريط تقدم حقيقي. النماذج المتاحة:

   | النموذج | الحجم التقريبي | الاستخدام المناسب |
   |---|---|---|
   | Base | ~142 MB | تجربة سريعة، أجهزة ضعيفة |
   | Small | ~190 MB | توازن جيد |
   | Medium (q5_0) | ~514 MB | دقة عالية للدارجة/الفرنسية، يحتاج ~2.5GB RAM متاحة |
   | Large-v3-Turbo (q5_0) | ~547 MB | أعلى دقة، يحتاج هاتفاً حديثاً بذاكرة كافية |

6. **بيانات لغة Tesseract**: ضع `ara.traineddata` و `fra.traineddata` في `tessdata/` — من https://github.com/tesseract-ocr/tessdata
7. **خط عربي لملفات PDF**: ضع خطاً يدعم العربية باسم `NotoNaskhArabic-Regular.ttf` في `assets/fonts/` — يُحمَّل مجاناً من Google Fonts (بحث "Noto Naskh Arabic")
8. `flutter run`

## البناء التلقائي عبر GitHub Actions (بلا حاجة لبيئة محلية)

- **عند كل `push`**: يعمل `.github/workflows/security-scan.yml` تلقائياً (فحص ثغرات + `flutter analyze`).
- **عند نشر Release جديد** (`Releases → Draft a new release → Publish`): يعمل `.github/workflows/release.yml` ويبني **APK (أندرويد) + مثبّت .exe (Windows) + AppImage و.tar.gz (Linux)** تلقائياً ويرفقهم بصفحة الإصدار. التفاصيل الكاملة في `SECURITY.md` (توقيع رقمي اختياري) و`PROJECT_STATE.md`.

## الأرشيف المحلي المشفَّر

كل تسجيل يُحفَظ تلقائياً بعد التفريغ الصوتي في قاعدة بيانات محلية مشفَّرة بالكامل (AES-256 عبر SQLCipher)، مع بحث وفلترة حسب الموضوع واللغة (زر 📁 في الشريط العلوي). مفتاح التشفير عشوائي (256 بت)، مُولَّد عند أول تشغيل ومخزَّن في خزنة النظام الآمنة (Android Keystore / Windows Credential Manager / Linux Secret Service) — تفاصيل التحقق من التشفير في `SECURITY.md`.

## ملاحظات دقة صريحة (مهم قراءتها قبل الاعتماد على أي مخرج)

- **فصل المتحدثين**: تقدير تقريبي بتحليل الطاقة الصوتية (RMS)، وليس نموذج تعرّف على الهوية الصوتية. يخطئ في القاعات الصاخبة أو عند تشابه مستوى صوت المتحدثين.
- **OCR**: يدعم العربية فعلياً عبر Tesseract (خلافاً لمعظم حلول OCR الجاهزة على الجوال)، لكن دقته على الخط اليدوي (سبورة) ضعيفة جداً — قيد تقني عام في المجال، وليس نقص تنفيذ.
- **الإجابة على الأسئلة (`local_rag_service.dart`) وتوليد الاختبارات (`quiz_generator_service.dart`)**: كلاهما **استخراجي (extractive)** — يبحثان عن أقرب جمل موجودة حرفياً في النص، ولا "يفهمان" أو يستنتجان أو يلخّصان. للحصول على إجابات مُصاغة فعلياً وأسئلة فهم حقيقية، يلزم دمج نموذج لغوي محلي (LLM) عبر مكتبات مثل `fllama` (llama.cpp) — نقطة تستحق نقاشاً ومرحلة بناء منفصلة.
- **تصدير PDF بالعربية**: يمر النص عبر `arabic_reshaper` لإصلاح اتصال الحروف، لكن هذا يتطلب وجود الخط في الخطوة 7 أعلاه — بدونه لن يظهر النص العربي بشكل صحيح في الـ PDF.
- **جودة الأسئلة المولَّدة**: تعتمد كلياً على طول وتنوع النص المُدخل. نص قصير جداً أو مكرر لن ينتج أسئلة ذات معنى.
- **لم يُصرَّف الكود (compile) في أي بيئة محلية حتى الآن** — راجع "نقاط غير مؤكدة" في `PROJECT_STATE.md` قبل الاعتماد الكامل على البناء الأول.

## الخطوة التالية المنطقية

اختبار ميداني حقيقي: `flutter pub get` أولاً للتأكد من عدم وجود أخطاء ترجمة، ثم تسجيل محاضرة فعلية على جهاز حقيقي، تجربة كل مرحلة بالتسلسل (تسجيل → أرشيف → اختبار → تصدير)، والتأكد من نجاح أول Release عبر GitHub Actions. التفاصيل الكاملة ونقطة الاستئناف الدقيقة في `PROJECT_STATE.md`.
